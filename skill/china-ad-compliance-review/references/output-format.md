# 输出格式

报告的唯一目的：让客户知道**这一版能不能发、哪里必须改、改不了要补什么**。

## 一、结构

```
# 广告审核意见

## 结论
（一句话。能发 / 改后能发 / 不能发。加一句为什么。）

## 必改（N 条）
### 1. 「原文摘录」
- 位置：正文第 2 段 / 主图右上角 / 口播 0:12
- 问题：（说清违反了哪条强制性规定，触发点在哪）
- 依据：《广告法》第九条第三项 —— <核验后的官方链接>
- 后果：依据第五十七条，法定罚款区间为 20 万–100 万元，情节严重可吊销营业执照 —— <核验后的官方链接>
- 修改：删除「」/ 改为「」

## 需补证（N 条）
### 1. 「原文摘录」
- 所需证据：（具体到什么报告、什么期间、什么口径）
- 取得前：不建议使用该表述 / 可改为「」

## 建议（N 条）
（不违法但有被认定风险的点，给替代写法）

## 其他核查事项
- 主体资质：……
- 素材时效：……
- 广告可识别性：……

## 本次审核范围
（审了什么、没审什么。例如：仅审文案，未审图片画面；未核验所提供报告的真实性。）
```

## 二、结论怎么写

第一句直接回答"能不能发"，三档：

| 情形 | 写法 |
|---|---|
| 无必改项、需补证项 | 「可以发布。有 2 项需在使用前补证，不涉及文案修改。」 |
| 有必改项 | 「不能按现稿发布。有 3 处表述违反强制性规定，修改后可发。」 |
| 有资质类阻断项 | 「不建议发布。该业务需取得 XX 许可，在取得前发布该广告将构成无证经营。」 |

**不要**用"总体合规，但建议注意……"这类模糊开头。客户读完第一句就该知道要不要继续改。

## 三、措辞规范

| 场景 | ❌ 不要写 | ✅ 写 |
|---|---|---|
| 客户没给证据 | 「涉嫌虚假宣传」 | 「该表述需第三方数据支撑，目前未提供」 |
| 客户给了证据 | 「需补充证明材料」 | 「已获知报告编号 XXX，请确认检测项目覆盖『XX』」 |
| 依据不确定 | 「根据相关规定」 | 「未检索到直接对应的现行条文，以下为同类执法口径参考」 |
| 法条 | 「违反广告法」 | 「违反《广告法》第九条第三项」+ 链接 |
| 内部标准 | 「不符合行业规范」 | 「不符合贵司《XX 规范》第 X 条（内部标准，非法律强制）」 |
| 修改建议 | 「建议优化表述」 | 「改为『……』」 |

## 四、责任后果怎么写

每条「必改」都要带后果，否则客户不会动。写三条规矩：

1. **给法定区间，不预测具体金额。** 「20 万–100 万」可以写，「大概会罚 30 万」不行。
2. **分清适用哪条罚则。** 绝对化用语走第 57 条（固定 20 万起，不看广告费）；行业违规走第 58 条（广告费 1–5 倍，无法计算按 10 万起）。搞错会被客户当场质疑。
3. **执法案例只用来佐证，不用来推算。** 需要时说「2025 年东阳市监、新昌县监有同类用语处罚案例，部分并处吊销许可证件」，附案号与链接。**不要**写「根据案例，你这版大概罚 X 万」。

批量审核时，责任后果只在同类问题首次出现时展开，后续条目写「同前，第 57 条」即可，避免报告变成法条复读机。

## 五、禁写项

- **禁止**出现内部字段名、缺陷编号、版本号、模型名
- **禁止**通篇"建议注意""务必谨慎""视具体情况而定"
- **禁止**引用法条而不给条款号与链接
- **禁止**把企业内部规则写成法律强制要求
- 把“本次为自动化风险筛查，不替代律师正式法律意见”放在范围声明中；该声明不得与具体修改结论相冲突
- **禁止**在未审画面的情况下暗示已审完整素材

## 六、范围声明必须真实

审核范围写清楚，是对自己也是对客户负责：

- 只审了文案 → 写明"未审图片/视频画面文字"
- 没核验报告真伪 → 写明"所提供材料的真实性未做核验"
- 地方性规定未查 → 写明"未检索投放地地方性规定"

范围写得虚，等于给客户一个错误的安全感，比漏检更麻烦。

## 七、交付形态

- 对话内直接给 Markdown，不默认生成文件
- 客户要正式文件时，再输出独立 HTML 或 Word
- 多条素材批量审时，先给一张汇总表（素材编号 / 必改数 / 需补证数 / 结论），再逐条展开
